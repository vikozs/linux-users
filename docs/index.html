RHEL 9 fleet operations

Find stale accounts, review the evidence, and remediate with both hands on the guardrails.

linux-users is a CLI tool for sysadmins and security teams that audits local accounts, sudoers, SSH keys, and last-login age across your fleet, then lets you lock or expire stale accounts only after review and live re-validation. Serious controls, light personality, no “oops, we deleted Bob.”

View repository See commands
What it does

Audits local accounts, password status, login age, sudoers, and SSH keys across RHEL 9 hosts.

What it changes

Only stale account lock/expire actions from a reviewed plan, with a fresh check before acting.

What it will not do

Never deletes accounts, never edits sudoers, and never removes SSH keys. The pager may still go off, but not because of that.

Core workflow

Discover → review → apply

The tool is built for cautious operators: inventory first, inspect the outputs, then apply only the plan you mean to apply.

1. Discover

Collect account, aging, sudoers, and SSH key data over SSH. Identify stale candidates, duplicate UID 0, empty passwords, weak keys, and risky sudo grants.

2. Review

Open the Excel report, inspect the machine-readable plan, confirm the findings, and protect any names you want excluded before the next step.

3. Apply

Lock stale accounts and optionally expire them, but only after a second discovery confirms they are still stale. If someone logged in since the audit, they drop out.

Guardrails

Designed to be boring in the best possible way

Never touched

  • root and every account with UID < 1000
  • The SSH account you connected with
  • Any name protected with --protect
  • Accounts with unknown or “never” last login status

Never modified

  • No userdel, ever
  • No sudoers edits
  • No SSH key removal
  • No password hashes collected into the plan

Operator-friendly

  • Per-host confirmation during apply
  • Passwords via stdin or SSHPASS, not CLI args
  • Formatted report for humans, JSON plan/results for automation
  • Re-validation before action, because change windows have a sense of humor

Outputs

Evidence for the spreadsheet crowd and the JSON crowd

users_report.xlsx

Formatted workbook with summary, accounts, stale candidates, sudoers, SSH keys, issues, errors, and an about sheet.

users_plan.json

Structured plan containing the same findings for review, automation, and later apply operations.

users_results.json

Apply-time record of what was actually locked per host after the re-check finished.

Usage

Typical operating sequence

Discover the fleet

python3 linux_users.py discover -H hosts.txt -u sa.vko \
    --ask-ssh-pass --sudo-pass-same-as-ssh

Apply the reviewed plan

python3 linux_users.py apply --plan users_plan.json -H hosts.txt -u sa.vko \
    --ask-ssh-pass --sudo-pass-same-as-ssh

Lock and expire with custom protection

python3 linux_users.py discover -H hosts.txt -u sa.vko --ask-ssh-pass \
    --sudo-pass-same-as-ssh --stale-days 120 --protect deploybot
python3 linux_users.py apply --plan users_plan.json -H hosts.txt -u sa.vko \
    --ask-ssh-pass --sudo-pass-same-as-ssh --expire

Re-render a report only

python3 linux_users.py report --plan users_plan.json -o report.xlsx
